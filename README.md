# PDE/SPDE Research Agent

目标：把“求解器调用”升级为一个**可运行、可评分、可纠错**的科研 Agent 工作流。  
适用任务：对给定 PDE/SPDE，在计算预算内自动选择时间步长与空间分辨率，满足误差要求并产出可复现实验结论。

---

## 1. Agent 闭环（核心能力）

Agent 必须执行以下闭环：

1. 理解方程与约束（边界/初值、噪声项、预算、误差阈值）
2. 选择数值方法（时间离散、空间离散、稳定性策略）
3. 调用求解器并记录配置
4. 验证结果（误差、收敛阶、稳定性、预算占用）
5. 诊断失败原因（发散、超时、内存不足、精度不达标）
6. 自动调整参数后重算（步长、网格、迭代容忍度、随机种子）
7. 输出报告（代码版本 + 实验数据 + 图表 + 结论）

---

## 2. 最小可运行环境规范

当前仓库是最小骨架（仅 README）。建议按以下结构补齐：

```text
.
├── solver/                 # PDE/SPDE 求解器实现
├── tasks/                  # 题目配置（方程、预算、误差目标）
├── runs/                   # 每次运行输出（日志、结果、图）
├── evaluator/              # 评分与验收逻辑
├── reports/                # 自动生成的实验报告
└── README.md
```

每次运行至少产出：

- `runs/<run_id>/config.json`：完整参数与随机种子
- `runs/<run_id>/metrics.json`：误差、耗时、内存、是否达标
- `runs/<run_id>/artifacts/`：误差表、收敛图、关键日志
- `reports/<run_id>.md`：自动结论与诊断建议

## 3. 任务输入与输出契约

### 输入（task）

建议使用统一配置（JSON/YAML）描述：

- 方程类型（PDE/SPDE）
- 维度与区域
- 初值/边界条件
- 噪声模型（SPDE）
- 误差阈值（如 `L2 <= ε`）
- 预算上限（时间/内存/算力）

### 输出（result）

结果必须机器可判定，至少包含：

- 是否达成误差目标（pass/fail）
- 最优参数（时间步长、网格分辨率）
- 误差与收敛信息
- 预算使用情况
- 若失败：失败类型 + 下一轮修正建议

---

## 4. 评分体系（可评分）

建议总分 100，示例权重：

- **正确性 50**：是否满足误差约束、收敛行为是否合理
- **效率 20**：在预算内完成且资源利用合理
- **鲁棒性 20**：多任务/多随机种子下稳定通过
- **可复现性 10**：固定 seed 可复现实验结论

### 建议通过门槛

- 硬门槛：误差达标 + 未超预算
- 软评分：在硬门槛内比较效率与稳定性

---

## 5. 自动纠错机制（可纠错）

当出现失败时，Agent 需进入纠错策略：

1. **识别失败类型**：发散 / 精度不足 / 超时 / 内存超限 / 随机波动过大  
2. **参数修正优先级**（示例）：
   - 精度不足：减小 `dt`、加密网格
   - 发散：切换更稳定格式或减小步长
   - 超时：放宽网格或启用更高效求解器
   - 波动大：增加样本数或控制随机种子
3. **再次运行并对比**：保留前后两轮指标，避免盲目回退
4. **终止条件**：达到目标或耗尽预算/最大迭代轮数

- [ ] 同一任务可一键复现（含依赖、命令、seed）
- [ ] 输出包含误差表和收敛图
- [ ] 评分脚本可自动给分并输出明细
- [ ] 失败时有可解释诊断与自动重试记录
- [ ] 报告包含方法、参数、结果、结论、局限

---

## 7. 项目定位

这个仓库的目标不是“单次算对”，而是构建一个能持续迭代的科研 Agent：

- 任务可标准化输入
- 结果可自动化验收
- 失败可结构化纠错
- 全流程可复现、可比较、可追踪
